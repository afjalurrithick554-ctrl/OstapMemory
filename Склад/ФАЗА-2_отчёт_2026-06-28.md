## 3. Что сделано

### Backend (правки в OM/, repo/ не трогали)
- **`open_notebook/domain/notebook.py`**: фикс subtask; новые поля `report`, `accepted`;
  каскадные переходы 0→1→2→3, обратимый гейт 3↔4 по `accepted`

- **`api/routers/notebooks.py`**: применение `report`/`accepted` в update; проброс
  `parent_id`/`report`/`accepted` во все ответы (get/update/list/children)
- **Миграция 18** (+down) и её регистрация в `async_migrate.py`

### Frontend (порт React → Vue 3)
- **Данные**: `@tanstack/vue-query` (`main.ts`), `api/notebooks.ts`, `types/notebook.ts`,
  `composables/useNotebooks.ts` (query/mutation + инвалидация), `lib/notebook.ts` (цвета/прогресс/время)

  секция архива; показывает только верхний уровень (подзадачи — внутри родителя)
- **Карточки** `NotebookCard.vue` / `NotebookRow.vue`: аура+цвет состояния, badge типа,

- **Создание** `CreateCellDialog.vue`: выбор cell/task, чеклист; режим подзадачи по `parentId`
- **Детальная** `views/NotebookDetailView.vue`: шапка + 3 колонки (`CollapsibleColumn`) + `ChildrenSection`
- **`NotebookHeader.vue`**: inline-правки имя/описание/тип/дедлайн (`DatePicker`)/исполнитель/план/чеклист;
  блок отчёта + кнопки «Принять»/«Вернуть на проверку»
- **Иерархия** `ChildrenSection.vue`: список подзадач + создание (всегда поведение task)
- **UI-примитивы**: Badge, Label, Textarea, Dialog, DropdownMenu, DropdownItem, DatePicker
- **Локали** ru+en: `states`, `notebooks`, `detail`

## 4. Проблемы, пойманные и устранённые

| Проблема | Причина | Решение |
|---|---|---|
| **`parent_id` не сохранялся** (иерархия сломана) | Таблица notebook — SCHEMAFULL, а поле `parent_id` нигде не объявлялось → SurrealDB молча отбрасывал его при сохранении подзадач | Объявлен в миграции 18 |
| `parent_id` отсутствовал в ответах get/update | Конструкции `NotebookResponse` его не передавали | Добавлен во все ответы |
| «Вернуть на проверку» не работал | `state` нет в `NotebookUpdate`, демоут был невозможен | Гейт 3↔4 сделан управляемым флагом `accepted` (4→3 при `accepted=false`) |
