# Отчёт: ФАЗА 5 — Остальные страницы, OstapMemory (Vue 3)

**Дата:** 2026-06-28
**Статус:** ✅ Собрана и проверена (визуальный прогон в браузере — за пользователем)
**Объём:** пять разделов — Progress, Search, Transformations, Podcasts, Settings (+ API-ключи). Это только фронт на Vue 3; бэкенд для всех страниц был скопирован ещё в ФАЗЕ 0 и правок логики не требовал.

---

## 1. Цель шага

Заменить пять `PagePlaceholder`-заглушек реальными страницами, портировав поведение из React-эталона `repo/`:
витрина состояний, поиск (текст/вектор/Ask), CRUD трансформаций, подкасты (эпизоды/генерация/профили)
и настройки с полным UI ключей и моделей (сюда переехала ручная настройка OpenRouter из ФАЗЫ 4).

---

## 2. Принятые решения (согласованы с пользователем перед сборкой)

| Вопрос | Решение |
|---|---|
| Объём фазы | **Все 5 страниц за один проход**, функционально (полировка — Фаза 6) |
| Settings / ключи | **Полный UI**: CRUD credentials, поиск/регистрация моделей по провайдеру, дефолтные модели, тест |
| Podcasts / Search | **Полно**: подкасты — список+плеер+генерация+профили; поиск — текст+вектор+Ask (RAG, SSE) |
| Источник разметки | **Порт из React-`repo/`** (как в Фазах 2–4) |

Уточнение по Progress: в React-эталоне это пустой `EmptyState`. Горизонтальная панель карточек «В работе» —
кастомизация OstapMemory из плана, поэтому Progress собран **по плану**, остальное портировано из React.

## 3. Что сделано (Frontend, новый код; бэкенд не трогали)

### Progress (`/progress`)
- `views/ProgressView.vue`: горизонтальная панель карточек в state=2 (переиспользован готовый `NotebookCard`),
  реактивно через `@tanstack/vue-query`, клик открывает ту же ячейку. Под панелью — пусто (расширим в Фазе 6).

### Search (`/search`)
- `types/search.ts`, `api/search.ts` (POST `/search` + SSE `/search/ask` через готовый `lib/sse.ts`),
  `composables/useSearch.ts` (`useSearch` + `useAsk` со стримингом стратегии/ответов/финала)
- `views/SearchView.vue`: вкладки **Спросить** (RAG, стриминг, markdown) и **Поиск** (text/vector,
  выбор «где искать», результаты со score и сворачиваемыми совпадениями). Векторный поиск гейтится наличием
  embedding-модели.

### Transformations (`/transformations`)
- `types/transformation.ts`, `api/transformations.ts`, `composables/useTransformations.ts`
- `components/transformations/TransformationCard.vue` (сворачиваемая, badge «по умолчанию», удаление),
  `TransformationEditorDialog.vue` (создание/правка)
- `views/TransformationsView.vue`: вкладки **Список** (сворачиваемый дефолтный промпт + карточки) и
  **Песочница** (выбор трансформации+модели, входной текст, запуск `execute`, markdown-результат)

### Podcasts (`/podcasts`)
- `types/podcast.ts`, `api/podcasts.ts` (эпизоды, генерация, ретрай, аудио-blob с авторизацией, CRUD профилей),
  `composables/usePodcasts.ts` (поллинг незавершённых, группировка статусов)
- `components/podcasts/`: `EpisodeCard.vue` (плеер + диалог Сводка/План/Транскрипт, ретрай, удаление),
  `GeneratePodcastDialog.vue`, `EpisodeProfileFormDialog.vue`, `SpeakerProfileFormDialog.vue` (до 4 спикеров)
- `views/PodcastsView.vue`: вкладки **Эпизоды** (счётчики статусов, генерация, группы по статусу) и
  **Шаблоны** (профили эпизодов и спикеров — список/создание/правка/удаление)

### Settings (`/settings`, `/settings/api-keys`)
- `api/settings.ts`, `api/credentials.ts`, расширен `api/models.ts` (create/delete/test/defaults-update/providers)
- `composables/useSettings.ts`, `useCredentials.ts`, расширен `useModels.ts`
- `lib/providers.ts` — справочник провайдеров, модальностей, типов моделей
- `components/settings/`: `CredentialFormDialog.vue` (провайдер, ключ с показом, base_url, модальности),
  `DiscoverModelsDialog.vue` (поиск моделей у провайдера → регистрация выбранных с типом),
  `DefaultModelsCard.vue` (дефолтные модели по типам)
- `views/SettingsView.vue` (обработка контента / эмбеддинги / файлы + переход к ключам),
  `views/ApiKeysView.vue` (credentials CRUD, тест, discover; список моделей по типам с тестом/удалением; дефолты)

### Прочее
- `router/index.ts`: пять заглушек заменены ленивыми импортами реальных view
- Локали ru+en: секции `progress`, `search`, `transformations`, `podcasts`, `settings`, `apiKeys`
  + ключи `common.{title,close,saved}`

## 4. Проблемы, пойманные и устранённые при проверке

| Проблема | Причина | Решение |
|---|---|---|
| `npm run build` падал: TS6133 `Loader2` не используется | Лишний импорт в `ApiKeysView.vue` (сборка `vue-tsc -b` включает `noUnusedLocals`, в отличие от `--noEmit`) | Импорт убран |
| Риск потери реактивности при `{ ...useQuery() }` | Спред результата vue-query в `usePodcastEpisodes` | Группировку статусов перенёс во view; composable возвращает чистый `useQuery` (как в остальном коде) |
| Числовое поле ломало типизацию `Input` | `Input` типизирован под `string`, а `num_segments` — число | Для числа использован нативный `<input type="number">` |

## 6. Открытые вопросы (на будущее)

- **Глобальная `/sources`** — осталась заглушкой (по решению ФАЗЫ 3, поиск/витрина источников — позже).
- **Расширенные поля credential** (Azure/Vertex/Ollama: endpoint, project, location, num_ctx) — в форме не выведены;
  поддержаны базовые (provider, key, base_url, modalities). Добавить при необходимости этих провайдеров.
- **Save-to-notebooks** и **Advanced models** в Ask — не портированы (полировка/командная палитра — Фаза 6).
- **Аудио-плеер**: тянет blob с авторизацией при готовности эпизода; потоковая отдача/перемотка — по необходимости.
- Удаления (эпизоды/профили/модели/credentials) — через `confirm()` или сразу; диалог-подтверждение с превью — Фаза 6.
- Потокенный стриминг Ask (как и чат) — целое сообщение; апгрейд до `astream` — отдельная задача.
- Фронт по-прежнему в dev-режиме (Vite). Prod-сборка (nginx) — на этапе polish.
