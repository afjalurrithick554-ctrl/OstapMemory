## 3. Что сделано

### Backend (новый код)
- `api/routers/feedback.py` — `POST /api/feedback` (`{element, comment}`), пишет JSON Lines
  в `{DATA_FOLDER}/dev_feedback.jsonl` с UTC-таймстампом. Зарегистрирован в `api/main.py`
  (импорт + `include_router(..., prefix="/api")`). Защищён тем же password-middleware.

### Frontend — Dev Mode
- `stores/dev.ts` — Pinia-стор тогла (не персистится, при загрузке выключен)
- `api/feedback.ts` — `sendFeedback()` через axios-клиент (с Bearer, в отличие от raw-fetch эталона)
- `components/dev/DevModeOverlay.vue` — глобальный слой: правый клик собирает CSS-путь элемента
  → модалка; вешает/снимает `dev-mode-active` на `<body>`, слушатель `contextmenu` в capture-фазе,
  игнорирует клики по `.dev-toggle` и `.dev-modal-overlay`
- `components/dev/DevFeedbackModal.vue` — модалка фидбека (путь элемента + textarea, Ctrl/Cmd+Enter)
- `components/dev/DevModeToggle.vue` — кнопка в сайдбаре (iconOnly для свёрнутого), красная при активном
- CSS в `assets/index.css`: `body.dev-mode-active *` — курсор-прицел + dashed-обводка при hover

### Frontend — Command Palette
- `components/common/CommandPalette.vue` — самодостаточная палитра на `reka-ui` Dialog:
  глобальный хоткей Cmd/Ctrl+K (capture, с пропуском в полях ввода), ручная фильтрация по
  label+keywords, навигация ↑/↓/Enter, mousemove-подсветка. Группы: Поиск/Спросить (по введённому
  тексту), Навигация, Ячейки (из `useNotebooks`), Создание (Новая ячейка → встроенный
  `CreateCellDialog`), Тема. Заголовок/описание скрыты через `VisuallyHidden` (a11y).
- Смонтирована в `AppShell`.

### Frontend — Error handling
- `components/common/ErrorBoundary.vue` — `onErrorCaptured`, запасной экран (сброс / перезагрузка),
  блок деталей ошибки. Оборачивает весь shell.
- `components/common/ConnectionGuard.vue` — пинг `/api/auth/status` на старте (всегда отвечает,
  вне middleware); во время проверки — спиннер, при ошибке — экран «нет связи» с кнопкой и хоткеем R.

### Frontend — Responsive
- `layout/AppShell.vue` — переработан: `ErrorBoundary > ConnectionGuard > layout`. Сайдбар статичен
  на `md+` (`hidden md:flex`), на мобиле — drawer-оверлей с backdrop + верхняя панель с гамбургером.
  Глобальные слои `DevModeOverlay` и `CommandPalette` подключены здесь.
- `layout/AppSidebar.vue` — проп `mobile` (drawer всегда развёрнут, без кнопки свёртки, клик по
  навигации закрывает drawer) + проброс `class`; добавлен `DevModeToggle` снизу.
- `stores/sidebar.ts` — добавлен `mobileOpen` + `openMobile/closeMobile`.
- `views/NotebookDetailView.vue` — на `<lg` три колонки Sources|Notes|Chat показываются как табы
  (видна одна активная); на `lg+` — все три в ряд, как раньше.
- `components/notebooks/CollapsibleColumn.vue` — добавлен проброс `class` (через `cn`) для
  управления видимостью колонки в табах.

### Локали
- ru-RU и en-US: секции `dev`, `command`, `errors` (использованы и существующие `common.*`).

## 4. Проблемы, пойманные и устранённые при проверке

| Проблема | Причина | Решение |
|---|---|---|
| `vue-tsc -b` падал: TS2339 `Property 'env' does not exist on ImportMeta` в `ErrorBoundary.vue` | `import.meta.env.DEV` не типизируется в SFC под сборкой проектных ссылок (`vue-tsc -b`), хотя `vite/client` объявлен | Убрана зависимость от `import.meta.env`; блок деталей ошибки показывается всегда (внутренний инструмент) |
| Бэкенд не видел новый роутер | Код бэка вшит в образ (volume только `./data`), а не монтируется | Пересобран и перезапущен контейнер `backend` |

## 6. Открытые вопросы (на будущее)

- **Контрольная правка дизайна (п.6 Фазы 6)** — отдельным проходом с браузером: визуальная
  полировка каждой страницы/вкладки.
- **Prod-сборка (nginx)** — Dockerfile фронта пока в dev-режиме (Vite, hot-reload); переключение
  отложено по решению.
- **Палитра: Создание источника/подкаста** — оставлено только «Новая ячейка» (source/podcast-создание
  привязано к контексту); расширить при необходимости.
- **Хоткей Cmd+K в полях ввода** — как и в React-эталоне, в обычных `input/textarea` палитра не
  открывается (чтобы не перехватывать ввод).
- **Разбор файла фидбека** — `data/dev_feedback.jsonl` читается вручную; UI-просмотр — по необходимости.
